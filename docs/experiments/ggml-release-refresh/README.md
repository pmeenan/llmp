# Native GGML release refresh

The native GGML closure now uses official llama.cpp **v0.6.0**, whose annotated tag peels to `d81235049384534c167caea52b85a694f6103d14` (GGML 0.26.0). The exact 37,887,730-byte archive has SHA-256 `6b58785f0a82898f4c3442417ff962e2d4b231b1bee5d033902ad90b27901e14`. The whole archive was inventoried for licenses, and the five local patches replayed through the shared exact parser without fuzz or offsets. The retained patched tree is `37947dde9e23668f876ec6cda08300f20b47588083b2269606dce57303990c0a`.

The migration preserves owned dispatch, compact routed worklists, padded scratch and the bounded IQ2 occupancy-two bridge. Upstream now supplies sparse query unions/live counts and D256 sparse eligibility; patch 0003 retains only D512 eight-query eligibility. MMQ planning, quantization and launch agree on Q4 activation packing for FP4 on Blackwell/GB10, and Q8 on other architectures and for other admitted formats. The bounded metadata validator admits undefined/Q4 minimum-source-precision requests for FP4 and undefined/Q4/Q8 for other quantized formats; explicit FP4 Q8 and higher minimum ranks are refused before planning. The owned build ignores the upstream precision environment override. Six float-vector selector calls now forward the actual physical warp size.

The F16-query attention derivative was refreshed from d812 with its query-type adaptation. Ordinary and owner planners use the new shared-memory swizzle/configuration and GB10 asynchronous whole-tile preference together. The target and assistant graph ports retain their b29 origins; updating their kernel dependency does not relabel those ports as d812 imports.

On Spark B, nine selected targets built and **43 focused controls passed with zero skips**. These cover compiled quantized formats against existing FP64 references, routed/compact/pair and DS4 D2R paths, attention/F16-query and whole-owner/partial-owner geometry, norms/ROPE and float GeGLU, and four real Gemma state-only/head-cap refusal, replay and restore cases. Three source contract checks passed. Thirty-six partial-owner plan records cover none, uniform and general fixups on both approved head counts; packed and independent-root outputs remain exact through eager execution and two poisoned capture replays.

The optional `--target` source audit passed for the nine built targets: 84,909 recorded dependency inputs across 251 outputs, using GGML, ds4, CUTLASS and GoogleTest. ExLlamaV3 and tomlplusplus are outside this focused closure. The default whole-build audit remains strict. Five no-compile controls check unknown, missing and stale outputs, virtual verification tasks, missing custom link inputs and explicit focused/full component coverage. The existing source-mechanism gates passed using the same new checker. Whole build/package closure is deferred.

The first native build failed on the changed MMVF API; its failed supervisor and compile-step statuses are retained. The first focused audit failed on virtual-task and component-scope handling after all 43 controls and three source checks had passed. Recovery ran only the audit, its controls and source mechanism. It did not repeat the passing operators. The measured helper and build receipt remain immutable. A separate metadata-only configure passed four source CTests and the same focused inventory. It registers the new control test and records the completed checks in the lock. Its final receipt differs only in the source-lock hash; no compiled math changed.

This closes the focused native integration slice. It provides no new end-to-end model quality, full-corpus likelihood, sustained performance or peak-memory qualification. Upstream FP4 accumulation and attention configurations changed, so historical model measurements remain evidence for their original pins. Runtime defaults and admitted models are unchanged. Spark A remained held for the owner; all remote heavy work ran serially on Spark B.
