# Bounded DeepSeek rounded consumer

This default-off foundation connects the existing rounded index score, visible
selection and selected mask in the shared component. It does not activate a
model mapping or qualify the DeepSeek migration. No external legacy bit pattern,
original-model quality threshold or speed claim governs this slice.

The real component graph uses completed positions and real compressed capacity,
not padded storage, to form visible counts. Selected IDs come from this
candidate's actual scores. Attention consumes one full raw-plus-compressed mask;
the raw window is not concatenated twice. Ordinary component emission is
unchanged when the policy is absent.

The real `ComponentStepSource` requires an owned, prepared backend and a complete
single-target numerical domain. It refuses absent/mismatched declarations,
unsupported phases/modes, joined owners, speculative uses, row-invariant policy,
borrowed state and out-of-domain actual shapes, including cached calls. Context
is 4–4096 and each ordinary single-owner step has at most eight rows. The policy
is included in existing source/plan/state identity. No new state-copy mechanism
or generic admission bypass is introduced.

## Evidence and its boundary

The isolated Spark B source build and 30 host controls passed (17 component and
13 execution-contract cases, no failures/skips). They exercise the real mapped
component graph and production source admission, including logical context257,
padded width256 and real capacity64. A separate fixed synthetic GPU case uses
the real declared/prepared `GgmlBackend` owner and the existing three operations.
It passed in 0.318 seconds of GoogleTest fixture time (one-second supervised
job), with three changed-input revisions and retained capture replay. This is a
correctness observation, not a performance comparison.

The GPU case checks all actual score-selected IDs, 192 raw half-bit values
(including infinities, signed zero and NaN payload bits), and 6,336 complete mask
entries. Counts cross completion boundaries and reach the real capacity64 while
256 stored cells remain padded. It retains complete ownership on unknown
completion and checks completed retirement before freeing resources.

The evidence is deliberately split: the actual GPU corridor is not a full
`ComponentStepSource` model execution. Full source GPU/model admission, kept
model continuation, full-mask fusion and family quality/speed gates remain open.
Main integration on Spark B passes its full native build and193 focused
host controls, followed by the same one-case GPU corridor in one supervised
second, with no failures/skips. The host set includes the17 real component and
13 execution-contract cases plus shared component, runner, decoder and
Qwen/DeepSeek lowering integration controls. Source code is unchanged from
the reviewed private result; main preserves its current lazy-input context
and multipart-row/capture implementations.
